# 🥃 100 ГРАМ

Свій Telegram, але «100 ГРАМ» — месенджер у реальному часі з реєстрацією, чатами,
власною валютою (ГРАМи) та преміум-підпискою. Статичний фронтенд на React,
весь бекенд — Firebase (Auth + Firestore), тому окремого сервера немає.

## Що всередині

- **Реєстрація та вхід** — email + пароль через Firebase Auth, вітальний бонус 500 ГРАМів
- **Чати в реальному часі** — приватні чати з живими оновленнями через Firestore, індикатор "друкує…"
- **Групи** — чат на кількох людей, писати можуть усі учасники
- **Канали** — публікувати можуть лише адміни (той, хто створив), решта тільки читає
- **Пошук користувачів** — знайти будь-кого за `@username` і почати чат
- **Профілі** — тапни на ім'я/аватар у чаті чи в списку учасників групи/каналу, щоб побачити біо, преміум-статус і написати
- **Гаманець "ГРАМи"** — власна валюта застосунку: атомарні перекази між користувачами (Firestore transactions), історія транзакцій
- **Поповнення карткою Аксіоми** — прив'язка віртуальної картки [Аксіома Банк](https://github.com/Ivanko-del/Aksioma) і поповнення ГРАМів з неї
- **Преміум-підписка** — плани на 1/6/12 місяців, оплата ГРАМами або напряму карткою Аксіоми, бейдж ⭐ біля імені
- **Управління групами й каналами** — перейменування, запрошення/кік/підвищення учасників, учасники при створенні необов'язкові
- **Фото та GIF у повідомленнях** — фото стискаються на клієнті (canvas → JPEG data URL) і зберігаються прямо в документі повідомлення (ліміт ~700КБ); GIF — лише за посиланням
- **Багаторядкові повідомлення** — Enter надсилає, Shift+Enter — новий рядок
- **Видалення повідомлень** — свої можна видаляти будь-де, адмін сайту — будь-які
- **Модерація** — сайт-адмін `@theivankoo` (жорстко зашитий у `firestore.rules` → `isSiteAdmin()` і `frontend/src/constants.ts` → `SITE_ADMIN_USERNAME`): глобальний мут, мут у межах чату, кастомні бейджі. Адмін бачить ці контролі в профілі будь-кого, включно з власним
- **Підтримка** — чат підтримки: Налаштування → Акаунт → «🆘 Підтримка»
- **Аватарки** — фото (base64 у Firestore, ~250КБ, дублюється в `memberProfiles` спільних чатів); Firebase Storage не використовується (потрібен план Blaze)
- **Телефон** — обов'язковий при реєстрації; SMS-підтвердження необов'язкове (Firebase Phone Auth, Налаштування → Акаунт). Підтверджений номер дає вхід за SMS-кодом; будь-який збережений номер — пошук друзями (`phones/{цифри}` → `{ uid }`)
- **Пароль на чати** — утримання чату → «Заблокувати паролем» (відкривається лише за паролем) або «Приховати» (зникає зі списку, лежить у ☰ → «Приховані чати»). Пароль хешується PBKDF2, дані в приватному `users/{uid}/private/chatlock`. Це захист від сторонніх очей, не шифрування
- **Підтримка** — пункт у боковому меню ☰
- **Екран «Нове повідомлення»** (кнопка «+») — пошук контактів, нова група, новий канал
- **Керування списком чатів** — утримання чату: закріпити, архів (ховається над списком, відкривається потягом вниз), видалити «у себе»; налаштування зберігаються в документі користувача (`pinnedChats`, `archivedChats`, `hiddenChats`)
- **Збережене** — особистий чат `saved_<uid>` з єдиним учасником
- **Налаштування пристрою** — розмір тексту, фон чату, компактний список, Enter надсилає (localStorage, `frontend/src/utils/prefs.ts`)
- **Налаштування** — профіль, тема, звук сповіщень, зміна пароля, видалення акаунта
- **Встановлюється як застосунок** (PWA) — на телефон (Android/iOS) і ПК (Windows/Mac/Linux) прямо з браузера, без App Store/Play Market

## Застосунок на телефоні та ПК

100 ГРАМ — це [PWA](https://web.dev/progressive-web-apps/): той самий сайт можна
"встановити" як звичайний застосунок з окремою іконкою та вікном без адресного рядка.

- **Android / Chrome / Edge (ПК)**: відкрити сайт → кнопка встановлення в адресному
  рядку, або Налаштування → Вигляд → «📲 Встановити застосунок» у самому 100 ГРАМ
- **iPhone/iPad (Safari)**: кнопка «Поділитися» → «На екран «Домій»» (iOS не підтримує
  автоматичний install-prompt — це обмеження самого iOS, не застосунку)

Реалізовано через `vite-plugin-pwa`: маніфест + service worker кешують лише статичний
код застосунку (HTML/JS/CSS/іконки) для офлайн-запуску — самі дані (чати, гаманець)
завжди йдуть напряму у Firebase, ніколи не кешуються, тому користувач завжди бачить
актуальний стан.

Нативних App Store/Google Play застосунків з цього репозиторію немає — для них
знадобився б окремий проєкт (Capacitor/React Native) і платні акаунти розробника
(Apple $99/рік, Google $25 одноразово), яких я не можу створити за тебе.

## Стек

- **Frontend**: React 18, TypeScript, Vite, React Router
- **Backend**: Firebase Authentication + Cloud Firestore (жодного власного сервера — фронтенд статичний і йде прямо на Vercel)

## Свідомі обмеження

- Без Firebase Storage і без Cloud Functions (обидва вимагають план Blaze) — тому немає ботів, а картинки живуть у Firestore як base64
- Правила Firestore **не деплояться автоматично**: після кожної зміни `firestore.rules` треба вручну вставити вміст у Firebase Console → Firestore Database → Rules → Publish
- Service worker використовує `skipWaiting` + `clientsClaim` (`registerSW({ immediate: true })`), тому нова версія підхоплюється без повного закриття PWA

## Налаштування Firebase (один раз)

1. Створи проєкт на [console.firebase.google.com](https://console.firebase.google.com)
2. **Authentication → Sign-in method** → увімкни **Email/Password**
3. **Firestore Database** → створи базу (Production mode)
4. **Firestore → Rules** → встав вміст файлу [`firestore.rules`](./firestore.rules) з кореня цього репозиторію і опублікуй
5. **Project settings → General → Your apps** → додай Web-застосунок, скопіюй `firebaseConfig`
6. Встав ці значення у `frontend/src/firebase.ts` замість `"REPLACE_ME"`

Значення `firebaseConfig` (apiKey, authDomain, projectId…) публічні за задумом Firebase —
безпеку забезпечують Firestore Security Rules, а не приховування цих полів,
тому їх спокійно можна тримати прямо в коді фронтенду.

## Деплой на Vercel

Це звичайний статичний Vite-застосунок — жодних змінних середовища не потрібно
(конфіг Firebase уже в коді). Framework Preset: Vite, Root Directory: `frontend`,
Build Command: `npm run build`, Output Directory: `dist`.

## Структура проєкту

```
firestore.rules          # Security Rules для Firestore (users, chats, messages, транзакції)
frontend/
  src/
    firebase.ts            # ініціалізація Firebase (App, Auth, Firestore)
    data/firestore-api.ts  # весь доступ до даних: auth, users, chats, messages, гаманець, преміум
    pages/                 # Login, Register, ChatPage, SettingsPage
    components/            # Sidebar, ChatWindow, MessageBubble, MessageInput, Avatar
    context/AuthContext.tsx
```

## Модель даних Firestore

```
usernames/{usernameLower}          -> { uid }                      // унікальність username
phones/{digits}                    -> { uid }                      // підтверджений номер: унікальність + пошук
users/{uid}                        -> профіль, ГРАМи, преміум
users/{uid}/transactions/{txId}    -> історія гаманця
chats/{chatId}                     -> memberUids, memberProfiles, adminUids, isGroup, isChannel, lastMessage
chats/{chatId}/messages/{msgId}    -> повідомлення (реалтайм через onSnapshot)
chats/{chatId}/typing/{uid}        -> ефемерний індикатор "друкує…"
```

Пряме повідомлення має детермінований id `dm_<uidA>_<uidB>` (uid відсортовані),
тому повторний пошук того самого співрозмовника відкриває той самий чат. Групи й
канали отримують випадковий id (`grp_…` / `ch_…`); те, хто в чаті може писати,
вирішує `isChannel` + `adminUids` — і на клієнті (ховається поле вводу), і в
`firestore.rules` (правило `create` для `messages` реально це блокує).

## Валюта ГРАМ

Кожен новий користувач отримує 500 ГРАМів на старт. Перекази та покупка преміуму
виконуються через `runTransaction` у Firestore — атомарно, без гонки станів.
Це ігрова валюта: правила Firestore не можуть повністю заборонити клієнту
редагувати власне поле `grams` напряму (для цього знадобились би Cloud Functions
на платному плані) — прийнятний компроміс для несерйозного застосунку, але
не варто зберігати тут щось цінне.

## Інтеграція з Аксіома Банком

[Аксіома Банк](https://github.com/Ivanko-del/Aksioma) — окремий проєкт з власною
віртуальною валютою (без реальних грошей), який використовується як спільна
"картка" для кількох застосунків одного автора. У Гаманці (Налаштування → Гаманець)
можна:

1. Увійти у свій акаунт Аксіоми (нік + пароль — окремі від акаунта 100 ГРАМ)
2. Прив'язати картку до профілю 100 ГРАМ (`link(username)`)
3. Списувати ₴ з картки й зараховувати ГРАМи (курс 1 ГРАМ = 1 ₴, `AXIOMA_EXCHANGE_RATE`
   у `frontend/src/axioma.ts`)
4. У вкладці Преміум — оплатити підписку напряму карткою Аксіоми, минаючи ГРАМи

Технічно Аксіома підключена окремим SDK (`frontend/public/axioma-sdk.js`, копія з
репозиторію Аксіоми) поверх Firebase v8 compat API (`firebase-app.js`, `firebase-auth.js`,
`firebase-database.js` у `index.html`) — це не конфліктує з основним Firebase-проєктом
100 ГРАМ, який використовує v9 modular SDK і Firestore, бо Аксіома ініціалізується як
окремий *named app* (`firebase.initializeApp(config, 'axioma')`) у своїй власній
Firebase-базі (Realtime Database), нею користуються `frontend/src/axioma.ts` та
хук `useAxioma`.

**Важливо:** щоб вхід в Аксіому працював з задеплоєного сайту (не тільки з
localhost), потрібно один раз додати домен Vercel у список дозволених доменів
на боці *проєкту Аксіоми* (не 100 ГРАМ): Firebase Console → проєкт `axioma-bank` →
Authentication → Settings → Authorized domains → додати домен виду
`100gram.vercel.app`. Без цього кроку вхід у Аксіому з задеплоєного сайту впаде
з помилкою `auth/unauthorized-domain`.
