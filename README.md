# 🥃 100 ГРАМ

Свій Telegram, але «100 ГРАМ» — месенджер у реальному часі з реєстрацією, чатами,
власною валютою (ГРАМи) та преміум-підпискою. Статичний фронтенд на React,
весь бекенд — Firebase (Auth + Firestore), тому окремого сервера немає.

## Що всередині

- **Реєстрація, вхід і відновлення пароля** — email + пароль через Firebase Auth (вітальний
  бонус 500 ГРАМів), «Забули пароль?» надсилає лист через стандартний флоу Firebase Auth
- **Чати в реальному часі** — приватні чати з живими оновленнями через Firestore, індикатор "друкує…"
- **Групи** — чат на кількох людей, писати можуть усі учасники; перейменування,
  запрошення/кик/промоут учасників, необов'язкові учасники при створенні
- **Канали** — публікувати можуть лише адміни (той, хто створив), решта тільки читає
- **Фото в повідомленнях** — стиснення на клієнті в base64 JPEG (без Storage/Blaze),
  + GIF за посиланням
- **Багаторядкові повідомлення** — Enter надсилає, Shift+Enter — новий рядок
- **Пошук користувачів** — знайти будь-кого за `@username` і почати чат
- **Профілі** — тапни на ім'я/аватар у чаті чи в списку учасників групи/каналу,
  щоб побачити біо, преміум-статус і написати; фото аватарки (теж base64 в Firestore)
- **Гаманець "ГРАМи"** — власна валюта застосунку: атомарні перекази між користувачами
  (Firestore transactions), історія транзакцій
- **Поповнення карткою Аксіоми** — прив'язка віртуальної картки [Аксіома Банк](https://aksioma-bay.vercel.app/)
  ([код](https://github.com/Ivanko-del/Aksioma)) і поповнення ГРАМів з неї; хто ще не має картки —
  посилання на реєстрацію прямо у вкладці Гаманець
- **Преміум-підписка** — плани на 1/6/12 місяців, оплата ГРАМами або напряму карткою
  Аксіоми, бейдж ⭐ біля імені
- **Адмін-модерація** — один хардкоджений сайт-адмін (`@theivankoo`): глобальний мут
  і мут у межах чату, кастомні бейджі користувачам, видалення будь-якого повідомлення
  (звичайний користувач може видаляти лише свої)
- **Чат підтримки** — Налаштування → Акаунт → «🆘 Підтримка»
- **Налаштування** — профіль, тема, звук сповіщень, зміна пароля, видалення акаунта
- **Встановлюється як застосунок** (PWA) — на телефон (Android/iOS) і ПК (Windows/Mac/Linux)
  прямо з браузера, без App Store/Play Market

## Застосунок на телефоні та ПК

100 ГРАМ — це [PWA](https://web.dev/progressive-web-apps/): той самий сайт можна
"встановити" як звичайний застосунок з окремою іконкою та вікном без адресного рядка.

- **Android / Chrome / Edge (ПК)**: відкрити сайт → кнопка встановлення в адресному
  рядку, або Налаштування → Вигляд → «📲 Встановити застосунок» у самому 100 ГРАМ
- **iPhone/iPad (Safari)**: кнопка «Поділитися» → «На екран «Домій»» (iOS не підтримує
  автоматичний install-prompt — це обмеження самого iOS, не застосунку)

Реалізовано через `vite-plugin-pwa` з `registerSW({ immediate: true })`: маніфест
і service worker (`skipWaiting`/`clientsClaim`, щоб оновлення не застрягали на
встановленому застосунку) кешують лише статичний код (HTML/JS/CSS/іконки) для
офлайн-запуску — самі дані (чати, гаманець) завжди йдуть напряму у Firebase,
ніколи не кешуються, тому користувач завжди бачить актуальний стан.

Нативних App Store/Google Play застосунків з цього репозиторію немає — для них
знадобився б окремий проєкт (Capacitor/React Native) і платні акаунти розробника
(Apple $99/рік, Google $25 одноразово), яких я не можу створити за тебе.

## Стек

- **Frontend**: React 18, TypeScript, Vite, React Router
- **Backend**: Firebase Authentication + Cloud Firestore (жодного власного сервера — фронтенд статичний і йде прямо на Vercel)
- **Якість коду**: ESLint (`npm run lint`), Vitest (`npm run test`) з юніт-тестами на чисті
  функції (нормалізація юзернейма, перевірка сайт-адміна), GitHub Actions CI
  (`.github/workflows/ci.yml`) ганяє lint + test + typecheck + build на кожен push/PR

## Налаштування Firebase (один раз)

1. Створи проєкт на [console.firebase.google.com](https://console.firebase.google.com)
2. **Authentication → Sign-in method** → увімкни **Email/Password**
3. **Firestore Database** → створи базу (Production mode)
4. **Firestore → Rules** → встав вміст файлу [`firestore.rules`](./firestore.rules) з кореня цього репозиторію і опублікуй
5. **Project settings → General → Your apps** → додай Web-застосунок, скопіюй `firebaseConfig`
6. Встав ці значення у `frontend/src/firebase.ts` замість `"REPLACE_ME"`

Значення `firebaseConfig` (apiKey, authDomain, projectId…) публічні за задумом Firebase —
безпеку забезпечують Firestore Security Rules, а не приховування цих полів,
тому їх спокійно можна тримати прямо в коді фронтенду.

**Важливо:** `firestore.rules` у репозиторії — це джерело правди, але Firebase
**не підхоплює його автоматично**. Кожна зміна файлу вимагає, щоб ти вручну
скопіював(ла) вміст у Firebase Console → Firestore Database → Rules → Publish.

## Деплой на Vercel

Це звичайний статичний Vite-застосунок — жодних змінних середовища не потрібно
(конфіг Firebase уже в коді). Framework Preset: Vite, Root Directory: `frontend`,
Build Command: `npm run build`, Output Directory: `dist`.

## Структура проєкту

```
firestore.rules          # Security Rules для Firestore (users, chats, messages, транзакції)
frontend/
  src/
    firebase.ts             # ініціалізація Firebase (App, Auth, Firestore)
    axioma.ts               # окремий named Firebase app для інтеграції з Аксіома Банком
    constants.ts             # сайт-адмін, вітальний бонус, ліміт довжини повідомлення, плани преміуму, кольори
    types.ts                # спільні типи (User, ChatSummary, ChatMessage, ...)
    data/firestore-api.ts   # весь доступ до даних: auth, users, chats, messages, гаманець, преміум
    data/firestore-api.test.ts, constants.test.ts  # юніт-тести (Vitest) на чисті функції
    pages/                  # Login, Register, ChatPage, SettingsPage
    components/              # Sidebar, ChatWindow, MessageBubble, MessageInput,
                              # Avatar, NewChatModal, MembersListModal, UserProfileModal, AxiomaCard
    hooks/                   # useAxioma, useInstallPrompt
    utils/                   # image.ts (стиснення фото), sound.ts
    context/AuthContext.tsx
```

## Модель даних Firestore

```
usernames/{usernameLower}          -> { uid }                      // унікальність username
users/{uid}                        -> профіль, ГРАМи, преміум, badge, mutedGlobally
users/{uid}/transactions/{txId}    -> історія гаманця
chats/{chatId}                     -> memberUids, memberProfiles, adminUids, mutedUids,
                                       isGroup, isChannel, lastMessage
chats/{chatId}/messages/{msgId}    -> повідомлення (text/image, реалтайм через onSnapshot)
chats/{chatId}/typing/{uid}        -> ефемерний індикатор "друкує…"
```

Пряме повідомлення має детермінований id `dm_<uidA>_<uidB>` (uid відсортовані),
тому повторний пошук того самого співрозмовника відкриває той самий чат. Групи й
канали отримують випадковий id (`grp_…` / `ch_…`); те, хто в чаті може писати,
вирішує `isChannel` + `adminUids` — і на клієнті (ховається поле вводу), і в
`firestore.rules` (правило `create` для `messages` реально це блокує).

## Валюта ГРАМ

Кожен новий користувач отримує 500 ГРАМів на старт. Перекази та покупка преміуму
виконуються через `runTransaction` у Firestore — атомарно, без гонки станів.
Це ігрова валюта: правила Firestore не можуть повністю заборонити клієнту
редагувати власне поле `grams` напряму (для цього знадобились би Cloud Functions
на платному плані) — прийнятний компроміс для несерйозного застосунку, але
не варто зберігати тут щось цінне.

## Фото без Firebase Storage

Фото аватарок і повідомлень стискаються на клієнті (`frontend/src/utils/image.ts`,
canvas → JPEG data URL) і зберігаються прямо в полі Firestore-документа, бо
Firebase Storage вимагає платного плану Blaze. Ліміти: аватарки ~250КБ (бо
дублюються в `memberProfiles` кожного спільного чату), фото повідомлень ~700КБ
(кожне повідомлення — окремий документ, без дублювання). Обидва — свідомий
компроміс, а не недогляд.

## Адмін-модерація

Один хардкоджений сайт-адмін — `SITE_ADMIN_USERNAME` у `frontend/src/constants.ts`,
і той самий рядок перевіряється незалежно в `firestore.rules` (`isSiteAdmin()`),
тому отримати ці права через devtools неможливо. Адмін може: глобально заглушити
користувача, муднути в межах чату, видати/зняти кастомний бейдж, видалити будь-яке
повідомлення. Щоб додати ще адмінів — потрібно змінити перелік імен в обох місцях.

## Інтеграція з Аксіома Банком

[Аксіома Банк](https://aksioma-bay.vercel.app/) ([код](https://github.com/Ivanko-del/Aksioma)) —
окремий проєкт з власною віртуальною валютою (без реальних грошей), який
використовується як спільна "картка" для кількох застосунків одного автора.
Хто ще не має картки, реєструється напряму на сайті Аксіоми (посилання є і
в самій картці гаманця в 100 ГРАМ — `AXIOMA_SITE_URL` у `frontend/src/axioma.ts`).
У Гаманці (Налаштування → Гаманець) можна:

1. Увійти у свій акаунт Аксіоми (нік + пароль — окремі від акаунта 100 ГРАМ)
2. Прив'язати картку до профілю 100 ГРАМ (`link(username)`)
3. Списувати ₴ з картки й зараховувати ГРАМи (курс 1 ГРАМ = 1 ₴, `AXIOMA_EXCHANGE_RATE`
   у `frontend/src/axioma.ts`)
4. У вкладці Преміум — оплатити підписку напряму карткою Аксіоми, минаючи ГРАМи

Технічно Аксіома підключена окремим SDK (`frontend/public/axioma-sdk.js`, копія з
репозиторію Аксіоми) поверх Firebase v8 compat API (`firebase-app.js`, `firebase-auth.js`,
`firebase-database.js` у `index.html`) — це не конфліктує з основним Firebase-проєктом
100 ГРАМ, який використовує v9 modular SDK і Firestore, бо Аксіома ініціалізується як
окремий *named app* (`firebase.initializeApp(config, 'axioma')`) у своїй власній
Firebase-базі (Realtime Database), нею користуються `frontend/src/axioma.ts` та
хук `useAxioma`.

**Важливо:** щоб вхід в Аксіому працював з задеплоєного сайту (не тільки з
localhost), потрібно один раз додати домен Vercel у список дозволених доменів
на боці *проєкту Аксіоми* (не 100 ГРАМ): Firebase Console → проєкт `axioma-bank` →
Authentication → Settings → Authorized domains → додати домен виду
`100gram.vercel.app`. Без цього кроку вхід у Аксіому з задеплоєного сайту впаде
з помилкою `auth/unauthorized-domain`.

## Повідомлення: вікно історії і пагінація

`subscribeMessages` тримає живий слухач лише на останні 50 повідомлень чату
(`orderBy("createdAt", "desc") + limit`, реверснуто для показу) — так новий
меседж завжди потрапляє у вікно, скільки б повідомлень до цього вже
назбиралось. Старіша історія довантажується одноразовим запитом
(`loadOlderMessages`) по кнопці «⬆ Завантажити старіші» зверху списку й не
живе-оновлюється, бо вона вже не змінюється. (Раніше запит був
`orderBy("createdAt", "asc") + limit(200)` — це давало фіксовані перші 200
повідомлень чату НАЗАВЖДИ: будь-що надіслане після 200-го повідомлення
просто не потрапляло у вікно запиту і не з'являлось у живому чаті. Виправлено.)

## Як перевірити стан проєкту швидко

```bash
cd frontend
npm run lint      # ESLint — 0 помилок (попередження не блокують)
npm run test      # Vitest — юніт-тести на чисті функції
npx tsc -b        # типи мають бути чисті
npx vite build    # білд має проходити без помилок
```

Усі чотири команди ганяються автоматично в GitHub Actions
(`.github/workflows/ci.yml`) на кожен push і pull request. Повноцінних
інтеграційних/e2e тестів немає (вимагали б живого Firebase-проєкту для
тестів) — живе QA йде вручну (тестування на телефоні/в браузері).
