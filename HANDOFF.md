# Передача сесії — 100 ГРАМ

Нотатка для наступної Claude-сесії (або для себе), що саме лишилось
незакінченим. Гілка: `claude/telegram-100-gram-clone-fuadhq`.

## Дизайн v2 ("технологічний")

Весь шар в кінці `frontend/src/styles/index.css` (блок "Design v2") - перекриває
старі плоскі стилі, нічого не ламає в розмітці. Глибокий темно-синій фон,
градієнти й світіння **похідні від `--accent-strong`** (тому преміум-вибір акценту
працює), скляні модалки, сітка на екрані входу, моноширинні цифри для ГРАМ
(JetBrains Mono), шрифт Inter (Google Fonts у `index.html`, є system fallback).
`data-powersave` вимикає blur/анімації. theme-color/manifest оновлено до #090b12.
Нові токени: `--grad`, `--glow-soft`, `--shadow-card`, `--font-ui`, `--font-mono`.
Не перевизначай `--accent`/`--bubble-own` у `:root` - це зламає вибір акценту.

## Аудит і виправлення багів (остання сесія)

Виправлено:
- **Deep-посилання давали 404 на Vercel** (`/join/...`, `/chat/...`, `/settings`):
  проєкт без framework preset не мав SPA-rewrite. Додано `vercel.json` (у
  `frontend/` і в корені, ідентичні) з rewrite на `/index.html`. Без цього
  запрошувальні посилання не відкривались у нових користувачів.
- **Безпека (`firestore.rules`)**: будь-хто міг створити профіль із
  `usernameLower: "theivankoo"` і стати адміном сайту. Тепер `users.create`
  вимагає резервацію username через `getAfter(usernames/..)` у тій самій
  транзакції. Також: `typing` пишуть лише учасники; адміни групи/каналу можуть
  видаляти повідомлення у своєму чаті.
- **Нове перше повідомлення в чаті не давало лічильник непрочитаних**
  (ChatPage мовчки "прочитував" такі чати). Тепер мовчки ініціалізуються лише
  старі чати без жодного `readBy` (`utils/unread.ts`, тести).
- Індикатор "друкує…" міг зависнути назавжди (немає нового snapshot) -
  `subscribeTyping` тепер перевіряє по таймеру; запис "друкує" не на кожну букву,
  а раз на ~2.5 с.
- Помилка слухача Firestore (kick із чату, відмова за правилами) лишала
  "Завантаження…" назавжди - тепер усі `subscribe*` віддають порожній стан.
- Видалення останнього повідомлення відкочує превʼю в списку чатів; видалення
  закріпленого знімає пін.
- Поповнення/преміум карткою Аксіоми: якщо після списання з картки запис у наш
  Firestore не вдався, гроші тепер повертаються (`chargeAxiomaThen`); сума
  поповнення лише ціла.
- `transferGrams`: валідація суми (ціле 1..1 000 000), порожнє/нецілe значення
  більше не дає дивної помилки правил.
- Прозорий PNG при стисненні ставав чорним (білий фон під JPEG).
- Помилка "Написати повідомлення" в профілі тепер показується, а не губиться;
  порожнє імʼя в профілі заборонене; ліміти довжини в опитуванні/редагуванні.
- Новий учасник групи/каналу не отримує всю історію як непрочитану.

Не чіпали (свідомо/відомо): будь-хто може піднімати чужі `grams` (ігрова валюта
без Cloud Functions), підробка `senderDisplayName`/реакцій клієнтом, спам-чати
через `chats.create` з чужими `memberUids`, вигнаного можна знову вступити в
публічний чат. Правила з `getAfter` у `users.create` **опубліковані користувачем, реєстрація нового
акаунта після цього перевірена і працює**. Якщо правила ще раз міняти - знову
перевіряти реєстрацію.

## Додано ще новішою сесією: розділи налаштувань у стилі Telegram

Користувач скинув скріни налаштувань Telegram і попросив додати такі ж функції
"по-нашому". Зроблено лише те, що реально працює без сервера:

- **Сповіщення** (`pages/settings/NotificationsTab.tsx`, `utils/notify.ts`): звук,
  сповіщення браузера коли вкладка у фоні (Notification API, **не** push при
  закритому застосунку), перемикач показу тексту, список вимкнених чатів. Для
  заблокованих/прихованих чатів текст ніколи не показується (`ChatPage.tsx`).
- **Папки для чатів** (`FoldersTab.tsx`, `utils/folders.ts`, `User.chatFolders`
  на документі користувача): власні вкладки над списком чатів у `Sidebar.tsx`
  (id `f:<id>`). Ліміт 3 безкоштовно / 10 з преміумом (`constants.ts`).
- **Економія енергії** (`PowerTab.tsx`, `utils/prefs.ts`): off/on/auto (авто - заряд
  <=20%, лише Chromium через Battery API). Ставить `data-powersave` на `<html>`,
  CSS вимикає анімації й blur.
- **Дані та сховище** (`DataTab.tsx`): обсяг кешу (`navigator.storage.estimate`),
  очищення кешу, скидання локальних налаштувань (ключі `stogram_*`).
- **Допомога**: "Поставити запитання" (чат з підтримкою), Часті питання, Можливості,
  Політика конфіденційності (`InfoTabs.tsx`) - тексти статичні, **політику
  користувачу варто перечитати й підправити під себе**.
- "Налаштування чатів" = стара вкладка без звуку; "Надіслати подарунок" веде в
  Гаманець (переказ ГРАМ).

**Свідомо НЕ робили** (немає як без сервера/сенсу): "Пристрої" (клієнт Firebase не
бачить список сесій), "Мова" (є лише українська, i18n - окрема велика робота),
Telegram Business. Зірки Telegram = наші ГРАМи (вкладка Гаманець).
Правила Firestore цією зміною **не мінялись**.

## Додано найновішою сесією: публічні/приватні групи й канали + нові налаштування

1. **Публічні й приватні групи/канали** (`ChatSummary.isPublic`, `inviteCode`).
   - Публічний (`isPublic: true`): знаходиться в пошуку (сайдбар і екран
     «Новий чат» - блок «Публічні групи та канали», `searchPublicChats`),
     будь-хто вступає сам кнопкою на `/join/:chatId` (`JoinPage.tsx`).
     Повідомлення лишаються тільки для учасників, до вступу видно назву,
     опис, кількість учасників.
   - Приватний (за замовчуванням, також усе старе без прапорця): вступ лише за
     посиланням `/join/:chatId?k=<inviteCode>`. Код створюється при створенні
     чату; адмін може оновити його (старі посилання помирають) або перемкнути
     видимість у модалці учасників (`MembersListModal`).
   - Вибір «Приватний/Публічний» є у формі створення групи/каналу.
   - Перехід за посиланням без логіну веде на логін і після входу повертає на
     `/join/...` (state `from` у `App.tsx`).
2. **Налаштування в стилі Telegram**: нав-колонка тепер велика аватарка з
   камерою, ім'я, @username і картки з кольоровими іконками (`NavRow` у
   `SettingsPage.tsx`, стилі `.settings-row` у `index.css`). Вкладки ті самі.

**firestore.rules змінились** (читання публічних чатів і `isSelfJoin()` для
самостійного вступу) - користувачу треба вручну republish-нути правила в
Firebase Console, інакше вступ/пошук дадуть `permission-denied`. Правила
**не тестувались** на емуляторі (з sandbox недоступно) - перевірити вручну:
вступ у публічний чат, вступ у приватний за посиланням, спроба вступити в
приватний без коду (має бути відмова).

Відомі обмеження: вигнаного з публічного чату можна знову вступити (немає
списку банів); пошук публічних чатів тягне до 200 публічних чатів і
фільтрує на клієнті (для великої кількості потрібен окремий індекс/сервер);
код запрошення бачать усі учасники чату (UI показує його лише тим, хто може
запрошувати).

## Додано попередньою сесією: пін повідомлень, опитування, @згадки

Користувач попросив "додати штуки з Telegram і Discord, які добре
доповнять 100 ГРАМ". Обрано три фічі, які реально бракувало (перевірено
грепом перед тим, як писати):

1. **Закріплене повідомлення** (`ChatSummary.pinnedMessageId`,
   `pinMessage()` в `firestore-api.ts`). Банер під заголовком чату
   (`.pinned-banner` в `ChatWindow.tsx`), клік веде до повідомлення через
   уже наявний `jumpTo`. Хто може пінити: будь-хто в DM, лише адмін у
   групі/каналі - рівно той самий бар, що й для перейменування/кіку, в
   `firestore.rules` новий `isPinChange()`.
2. **Опитування** (`PollData` в `types.ts`: `question`, `options`,
   `votes` - map optionIndex→uids). Повідомлення з `type: "poll"`.
   Кнопка 📊 в `MessageInput.tsx` відкриває інлайн-форму (питання + 2-10
   варіантів). Голосування - `votePoll()`, одноразовий вибір (новий голос
   забирає попередній). `firestore.rules`: голосування може торкатись
   лише `poll.votes` - є explicit перевірка `pollVoteOk()`, що
   `question`/`options` не змінились, інакше голосування можна було б
   використати, щоб переписати текст опитування.
3. **@Згадки** (`utils/mentions.tsx`, `renderWithMentions()`) - **суто
   косметика на рендері**, ніякого запису в Firestore: регулярка
   підсвічує `@word`-токени в тексті повідомлення. Свідомо не резолвиться
   в реальних учасників чату і не впливає на сповіщення/мут - це дало б
   цінність, але вимагало б передавати список учасників у MessageBubble і
   чіпати логіку мута, а для "просто щоб було видно" непропорційно.

Пересилання (`forwardTo`) і цитата-відповідь (`replyTo`) оновлені, щоб не
ламались на повідомленні типу `poll` (пересилання опитування скидає
голоси - летить як новий "чистий" poll з тим самим питанням/варіантами).

**Що свідомо НЕ зробили з "Telegram і Discord" списку** (вимагали б
сервера/Cloud Functions/реальної інфраструктури, яких у проєкту немає):
голосові повідомлення (можна спробувати MediaRecorder + base64, як фото,
але аудіо стискається гірше й ризикує впертися в ліміт документа 1MB -
не робили, бо не встигли протестувати на реальному Firebase з цього
sandbox), дзвінки (WebRTC + сигнальний сервер - велика окрема робота),
прев'ю посилань (потребує серверного фетчу og:meta, inaccessible з
клієнта через CORS), множинний вибір повідомлень для масового видалення
(непогана ідея на майбутнє, просто не влізло в цю сесію).

Перевірено: `npm run lint && npm run test && npx tsc -b && npx vite build`
- усе чисто (0 помилок лінтера, 17/17 тестів, білд ОК).

**Firestore rules змінились** (`isPinChange()`, `pollVoteOk()` і новий
update-branch для `poll`) - як завжди, користувачу треба вручну
republish-нути `firestore.rules` у Firebase Console, інакше пін і
голосування впадуть з `permission-denied`.

## Свідомі архітектурні рішення (не пропонуй їх "виправити")

- **Без Firebase Storage і без Cloud Functions** (обидва вимагають план
  Blaze) — тому немає ботів, а картинки живуть у Firestore як base64.
  Аватарки: ліміт ~250КБ (дублюються в `memberProfiles`). Фото повідомлень:
  ліміт ~700КБ (окремий документ).
- **GIF тільки за посиланням**, не завантаженням файлу — свідомий вибір
  користувача.
- **Один хардкоджений сайт-адмін** — `SITE_ADMIN_USERNAME = "theivankoo"`
  в `frontend/src/constants.ts`, той самий рядок в `firestore.rules`
  (`isSiteAdmin()`). Не self-settable.
- **`eslint-plugin-react-hooks` навмисно обмежено** двома класичними
  правилами (`rules-of-hooks`, `exhaustive-deps`) замість повного v7
  `recommended` preset — той тягне нові React Compiler-правила
  (`set-state-in-effect`, `refs`, `purity`, ...), які зафлагували б як
  помилки усталені React 18 патерни по всьому коду (напр. `setLoading(true)`
  на початку data-fetching ефекту).
- **ГРАМи редагуються клієнтом напряму** — реальна server-side цілісність
  вимагала б Cloud Functions на платному плані. Прийнятний компроміс для
  ігрової валюти.

## Правила Firestore — ручна публікація, не автодеплой

`firestore.rules` у репозиторії — джерело правди, але Firebase **не
підхоплює його автоматично**. Кожна зміна вимагає, щоб користувач вручну
вставив вміст у Firebase Console → Firestore Database → Rules → Publish.
Поточна версія (з `phones/{phone}`, `users/{uid}/private/{doc}` для
pardon-на-чат) **підтверджена опублікованою** користувачем раніше.
Цю сесію `firestore.rules` не редагували вручну — лише git-мердж з `main`
(без конфліктів), тому вміст не змінився відносно того, що вже на `main`.

## Деплой і гілки

- `main` і `claude/telegram-100-gram-clone-fuadhq` зараз ідентичні (див.
  розділ вище) — **обов'язково тримай їх так і надалі**: якщо комітиш у
  гілку, познач це в HANDOFF і фактично фаст-форварднь `main` разом з нею
  (`git push origin HEAD:main`), інакше розбіжність повернеться й знову
  зламає прод користувачу.
- Vercel-проєкт `100gram-dcz1`: за попередньою нотаткою, автодеплой з
  `main` міг створювати лише preview (Production Branch у Settings → Git,
  можливо, не `main`), і production доводилось викочувати вручну через
  `create_deployment` з `target: production`. Якщо ще не перевірено цю
  сесію — варто зайти в Vercel Settings → Git і виставити Production
  Branch = `main`, щоб push у `main` сам тягнув production без ручного кроку.
- `firestore.rules` — вручну в Console → Publish, користувач підтвердив
  останню версію опублікованою.

## Відомі обмеження

- SMS-верифікація телефону написана, але з Claude-сесій живо не
  тестувалась (мережевий проксі блокує Firebase ендпоінти). Потрібен план
  Blaze, провайдер Phone увімкнений, домен застосунку в Authentication →
  Settings → Authorized domains.
- «Видалити чат» = сховати у себе (`hiddenChats`), для груп/каналів це не
  вихід із чату.
- Push-сповіщення при закритому застосунку, голосові/файли/відео, стікери
  й кастомні емодзі — потрібні Cloud Functions/Storage (план Blaze).
  Глобальний пошук по всіх повідомленнях і запрошувальні посилання в групи
  — потребують сервера або складніших правил. Захист ГРАМів і преміуму від
  підробки з клієнта — також лише через Cloud Functions.
- `npm audit` у `frontend/` показує вразливості в `@grpc/grpc-js`
  (транзитивна через `firebase`), `esbuild`/`vite`, `react-router`, і
  критичну в `vitest` (стосується лише `vitest --ui`, який проєкт не
  використовує). Усі фікси вимагають мажорних апгрейдів з `--force` —
  свідомо не робили автономно, це вимагає живого тестування проти Firebase.

## Як перевірити стан проєкту швидко

```bash
cd frontend
npm install       # package.json змінився цю сесію
npm run lint      # ESLint
npm run test      # Vitest
npx tsc -b        # типи мають бути чисті
npx vite build    # білд має проходити без помилок
```

Живе тестування Firebase з Claude-сесій не працює (мережевий проксі блокує
auth/firestore ендпоінти) — QA йде через статичний аналіз
(lint/build/unit-тести) плюс ручне тестування користувачем на
задеплоєному сайті.
