# Передача сесії — 100 ГРАМ

Нотатка для наступної Claude-сесії (або для себе), що саме лишилось
незакінченим. Гілка: `claude/telegram-100-gram-clone-fuadhq`.

## ВИРІШЕНО цю сесію: дві розбіжні гілки злито, main і ця гілка ідентичні

Якийсь час існували **дві незалежні лінії розробки**:
`claude/telegram-100-gram-clone-fuadhq` (ця гілка) і `main` — вони розійшлись
у точці "Додати HANDOFF.md" і відтоді `main` отримав ~20 комітів із купою
фіч (SMS-вхід, повний редизайн у стилі Telegram, реакції/відповіді/пересилання,
непрочитані, справжній last seen, пароль на чати, блокування користувачів),
яких на цій гілці не було. Користувач побачив регресію ("дизайн і деякі
функції змінилися на старі") — причина саме в цьому.

**Виправлено й підтверджено користувачем** ("все є"): `origin/main` злито в
цю гілку, після чого цю ж саму гілку fast-forward-нуто в `main`
(`git push origin HEAD:main`) — обидві гілки на GitHub зараз вказують на
**один і той самий коміт** (`123a4f6` на момент запису). Нічого далі
робити з гілками не треба, якщо хтось знову не почне комітити в `main`
окремо від цієї гілки.

Для довідки, як саме розв'язано конфлікти (на випадок якщо знову доведеться
мержити розбіжні гілки):
- `ChatWindow.tsx`, `ErrorBoundary.tsx`, `MessageInput.tsx`, `AuthContext.tsx`,
  `Login.tsx`, `main.tsx`, `firestore-api.ts` — узято версію з `main` цілком
  (вона була строго повніша в кожному місці перетину: main вже мав власний
  working відновлення пароля, ErrorBoundary, фікс пагінації повідомлень
  desc+limit+reverse — усе те, що ця гілка винайшла наново паралельно).
- `normalizeUsername` в `firestore-api.ts` залишено `export`-нутим (для
  тестів цієї гілки — `data/firestore-api.test.ts`, `constants.test.ts`,
  main таких тестів не мав).
- `package.json`/`package-lock.json` — узято devDependencies з обох: ESLint
  (`eslint.config.js`, тільки класичні `rules-of-hooks`+`exhaustive-deps`,
  **не** повний v7 `recommended` preset — див. нижче чому) додано до того,
  що вже мав `main` (vitest, тести `lastSeen.test.ts`/`phone.test.ts`).
- `AxiomaCard.tsx`/`axioma.ts` — конфліктів не було (main їх не торкався),
  лишилось посилання на реєстрацію (`AXIOMA_SITE_URL = "https://aksioma-bay.vercel.app/"`).
- README.md/HANDOFF.md — переписані вручну з нуля на основі версії `main`
  (вона набагато повніша) + додані секції про ESLint/Vitest/CI з цієї гілки.
- `.github/workflows/ci.yml` — новий, `main` його не мав.

Після мерджу усе перевірено: `npm run lint && npm run test && npx tsc -b && npx vite build`
пройшли чисто (0 помилок лінтера, 14/14 тестів, білд ОК).

## Без відповіді з попередньої сесії (main)

Користувач написав «Преміум дуже дешевий і майже не потрібний» —
незрозуміло, чи прибрати вкладку, чи підняти ціни. Ціни вже підняли
(500/2400/4200 ГРАМ), але чи це остаточна відповідь на коментар — не ясно.

## Свідомі архітектурні рішення (не пропонуй їх "виправити")

- **Без Firebase Storage і без Cloud Functions** (обидва вимагають план
  Blaze) — тому немає ботів, а картинки живуть у Firestore як base64.
  Аватарки: ліміт ~250КБ (дублюються в `memberProfiles`). Фото повідомлень:
  ліміт ~700КБ (окремий документ).
- **GIF тільки за посиланням**, не завантаженням файлу — свідомий вибір
  користувача.
- **Один хардкоджений сайт-адмін** — `SITE_ADMIN_USERNAME = "theivankoo"`
  в `frontend/src/constants.ts`, той самий рядок в `firestore.rules`
  (`isSiteAdmin()`). Не self-settable.
- **`eslint-plugin-react-hooks` навмисно обмежено** двома класичними
  правилами (`rules-of-hooks`, `exhaustive-deps`) замість повного v7
  `recommended` preset — той тягне нові React Compiler-правила
  (`set-state-in-effect`, `refs`, `purity`, ...), які зафлагували б як
  помилки усталені React 18 патерни по всьому коду (напр. `setLoading(true)`
  на початку data-fetching ефекту).
- **ГРАМи редагуються клієнтом напряму** — реальна server-side цілісність
  вимагала б Cloud Functions на платному плані. Прийнятний компроміс для
  ігрової валюти.

## Правила Firestore — ручна публікація, не автодеплой

`firestore.rules` у репозиторії — джерело правди, але Firebase **не
підхоплює його автоматично**. Кожна зміна вимагає, щоб користувач вручну
вставив вміст у Firebase Console → Firestore Database → Rules → Publish.
Поточна версія (з `phones/{phone}`, `users/{uid}/private/{doc}` для
pardon-на-чат) **підтверджена опублікованою** користувачем раніше.
Цю сесію `firestore.rules` не редагували вручну — лише git-мердж з `main`
(без конфліктів), тому вміст не змінився відносно того, що вже на `main`.

## Деплой і гілки

- `main` і `claude/telegram-100-gram-clone-fuadhq` зараз ідентичні (див.
  розділ вище) — **обов'язково тримай їх так і надалі**: якщо комітиш у
  гілку, познач це в HANDOFF і фактично фаст-форварднь `main` разом з нею
  (`git push origin HEAD:main`), інакше розбіжність повернеться й знову
  зламає прод користувачу.
- Vercel-проєкт `100gram-dcz1`: за попередньою нотаткою, автодеплой з
  `main` міг створювати лише preview (Production Branch у Settings → Git,
  можливо, не `main`), і production доводилось викочувати вручну через
  `create_deployment` з `target: production`. Якщо ще не перевірено цю
  сесію — варто зайти в Vercel Settings → Git і виставити Production
  Branch = `main`, щоб push у `main` сам тягнув production без ручного кроку.
- `firestore.rules` — вручну в Console → Publish, користувач підтвердив
  останню версію опублікованою.

## Відомі обмеження

- SMS-верифікація телефону написана, але з Claude-сесій живо не
  тестувалась (мережевий проксі блокує Firebase ендпоінти). Потрібен план
  Blaze, провайдер Phone увімкнений, домен застосунку в Authentication →
  Settings → Authorized domains.
- «Видалити чат» = сховати у себе (`hiddenChats`), для груп/каналів це не
  вихід із чату.
- Push-сповіщення при закритому застосунку, голосові/файли/відео, стікери
  й кастомні емодзі — потрібні Cloud Functions/Storage (план Blaze).
  Глобальний пошук по всіх повідомленнях і запрошувальні посилання в групи
  — потребують сервера або складніших правил. Захист ГРАМів і преміуму від
  підробки з клієнта — також лише через Cloud Functions.
- `npm audit` у `frontend/` показує вразливості в `@grpc/grpc-js`
  (транзитивна через `firebase`), `esbuild`/`vite`, `react-router`, і
  критичну в `vitest` (стосується лише `vitest --ui`, який проєкт не
  використовує). Усі фікси вимагають мажорних апгрейдів з `--force` —
  свідомо не робили автономно, це вимагає живого тестування проти Firebase.

## Як перевірити стан проєкту швидко

```bash
cd frontend
npm install       # package.json змінився цю сесію
npm run lint      # ESLint
npm run test      # Vitest
npx tsc -b        # типи мають бути чисті
npx vite build    # білд має проходити без помилок
```

Живе тестування Firebase з Claude-сесій не працює (мережевий проксі блокує
auth/firestore ендпоінти) — QA йде через статичний аналіз
(lint/build/unit-тести) плюс ручне тестування користувачем на
задеплоєному сайті.
